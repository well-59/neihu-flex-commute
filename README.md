# 內湖時間島

**目前版本：v9 內湖道路監控模型島** — 內湖園區搞清楚要走的路。

預設開啟即時監控：依官方區界分類的 **52 個現行 VD、80 個設備方向、21 個道路名稱**全部保留並對照至模型道路。已補入東湖路、成功路五段、成功路四段、文德路；共用 LinkID 的測點仍可分別檢視，動畫不加總重複設備的流量。道路名稱／方向可搜尋、鍵盤選取，點路段或標籤可看速度、路況等級與依據、汽機車分鐘量、觀測時間、偵測車道與 VD／LinkID。

桌面以左右可收合面板保留地圖空間；手機以地圖、持續可見圖例及下方資訊卡呈現。全景依擴展圖資與實際可視範圍取景，點路段可聚焦。色帶位於車輛下方；車輛沿實際路徑弧長移動，保留單行、明示通行限制、路網分層與已保存轉向限制。條件式方向尚未解析的道路保留路況但暫停車流動畫；路口未知分岔不推定合法轉向。

路況色彩為通暢／車速下降／壅塞／嚴重壅塞／灰色無有效路況。適用且精確對照的官方級別、依既有道路門檻試算及本地速度色帶分別標示，試算不是官方發布。零流量而無有效速度、過期、來源失敗與不完整資料不補成綠色。灰色不表示順暢，色帶只表示對應觀測路段，不外推整條道路；此頁不是導航或全路網排隊預測。

新圖資來源、重建及區界精度見 [監控道路資料說明](docs/MONITORED-ROADS.md)。歷史／錯峰頁仍使用原有資料口徑；下方歷史快照數字不代表新的完整監控清單。

## 啟動

需要 Node 24；不用安裝前端套件或執行 build。

```sh
node scripts/negotiation-server.mjs
```

開啟 <http://127.0.0.1:4173/traffic-island.html>。一般靜態伺服器開啟 `web/index.html` 也會導向 3D 版。

即時監控每 60 秒向本機 `/api/monitoring` 查詢，伺服器從四份臺北市官方公開 XML 取得資料，不使用 TDX 金鑰。離開即時頁即停止輪詢；單一 HTML 與純靜態服務提供歷史回放及已保存的 VD 盤點，不提供此 API。來源超過 3 分鐘即停用；速度使用官方路段或 VD 車道加權速度，動畫為流量分級與統一 4 倍時間縮放，並非逐車追蹤。

設備數、道路名稱、路段編碼與來源 URL：[監控盤點](docs/MONITORING-INVENTORY.md)、[逐方向 CSV](docs/MONITORING-INVENTORY.csv)、[完整 JSON](docs/MONITORING-INVENTORY.json)。盤點與即時顯示是不同時間的快照，數量可能變動。重新盤點：`python3 scripts/monitoring-snapshot.py --report`。

VD 位置頁以已保存盤點為起點，也可手動更新。128 個設備中 104 個位於擴展底圖內；24 個圖外設備保留清單與 OpenStreetMap 座標連結。點位保留官方 WGS84 座標，不吸附到鄰近道路；TDX 線形只依相同設備、LinkID、道路與路段方位對照，虛線不表示感測範圍。觀測時間、分鐘資料發布時間、本機接收時間分開顯示；設備每日實際啟停時段未提供。

2026-10-24 方向欄位更正：先前公開 XML 解析以 `RoadDirection` 填入 `bearing`，現改讀 `Bearing`，另保留 `roadDirection`。`RoadDirection` 表示道路方向，`Bearing` 表示局部路段方位；本批 43 筆不同，23 筆涉及既有歷史對照。依[官方欄位定義](https://thbapp.thb.gov.tw/opendata/vdinfo.aspx)修正，以免彎道路段被判成方向不符。歷史快照與使用者的下載 XML 不改動。

更新保存盤點後，執行 `node scripts/export-vd-inventory.mjs` 再執行 `node scripts/export-traffic-island.mjs`，同步設備頁與單檔。單檔含設備盤點，但不提供手動即時更新。

### 部署（Vercel）

`vercel.json` 以 `web/` 為靜態網站，`api/monitoring.py`（呼叫同一份 `monitoring-snapshot.py`，CDN 共用快取 60 秒）與 `api/places.mjs`（同一份 Photon 搜尋與限流，只接受同網域頁面）取代本機 API；`.vercelignore` 只上傳 `web/`、`api/`、`scripts/`，本機 `data/` 不上傳。歷史協商頁的 Claude CLI 橋接不部署。

```sh
npx vercel@latest deploy --prod
```

`negotiation-server.mjs` 是沿用的本機預覽服務名稱，也保留歷史協商頁的可選 Claude CLI 橋接；目前 3D 功能不依賴 Claude。它只監聽本機，不是公開部署用伺服器。

## 分時路段比較

路段分析以長橫向色帶呈現：每列是一個路段測點方向，10 格分別顯示 07:00–07:15 至 09:15–09:30 的低速時間占比，固定對齊以比較同一時段。點色格留在分析頁，展開該格車次、反覆低速日數與完整度；另按明細按鈕才切地圖。手機橫捲時固定路名；同路名方向以 VD 編號區分。整段晨峰概況在 3D 版收合保留。百分比是低速分鐘／可判讀分鐘，不是平均速度、塞車車輛比例或遇到塞車機率。車次來自另存公開 CSV，與原多日低速分級的有效分鐘口徑不同，分開揭露樣本日與分母。

重建與來源限制見 [歷史收集資料](dataset/README.md)。多日快照及動畫不變；分時車次不由晨峰平均值乘以 15，也不加總為不重複進園總量。駕駛可比較歷史時段，實際改道須查看即時監控，且目前沒有替代路線的連通、合法轉向與旅時驗證。

## 動態島道路點選與分時連動

歷史城市回放可滑鼠移過或點選目前底圖道路：提示實際圖資路名、所選 15 分鐘時段與可對照的低速時間占比；點選後在同一頁下方呈現該觀測方向的 10 格色帶，切格同步右側明細。觀測範圍外的已知道路會切換全部範圍；未配對道路顯示缺資料，不沿用上一條路的數值。顏色與分析色帶採同一顯示級距；未修改車流動畫、原始觀測與路網拓樸。

目前底圖的 549 個道路圖徵、4,056 個方向小段都有點選幾何；其中 977 個小段可依既有路名、方向與線形對照觀測。這是目前底圖範圍的互動覆蓋，不代表內湖所有道路已有感測器或道路拓樸、導航轉向、觀測代表範圍已完整驗證。既有幾何對照仍含距離容許值，不能宣稱逐車道或全程旅速精度。

瀏覽器檢查：`node tests/road-inspector-browser.cjs`（專用 Chrome，預設 CDP 9345，可由 `NEIHU_3D_CDP` 指定）。包含原始方向邊覆蓋、實際滑鼠點選、有／無資料、跨範圍、時段同步、平面／高架點選分層、單檔及手機版。

## 彈性工時獎勵與獎勵兌換商品

2026-10-24 依使用者需求新增兩個選單頁，串起「政府提供分析與誘因 → 企業依方向設定彈性工時 → 上班族錯峰到班累積點數 → 兌換商品」的減塞設計。

**彈性工時獎勵**（`?view=flex`）：選公司位置（公共地標約略座標、自訂座標或在 3D 地圖選點，不預設真實企業）、上班時間（07:00–09:30，每 15 分鐘）、範圍（預設 2 公里）與壅塞門檻 θ（預設 50%）。頁面以羅盤標示公司東南西北四個方向與周邊 VD 測點，逐方向計算建議彈性工時：

1. `s(r,t)` = 低速分鐘 ÷ 可判讀分鐘（整段期間、排除國定假日）；`h(r,t)=1` 若 `s ≥ θ`。
2. 壅塞時段占可判讀時段 ≥ 80% 的道路列為「全早壅塞」，調整時間也避不開，另外列出、不計入下一步。
3. `n(D,t)` = 方向 D 在時段 t 同時壅塞的道路數；`n* = max n`；最大集合塞車時段 `W=[a,b)` 為 `n ≥ 0.8·n*` 且含 n* 的連續時段，優先取與核心時段重疊者。
4. 核心時段 `C=[T−15, T+15)`；W 與 C 重疊時 `F = min(120, max(30, ⌈max(T−a, b−T)+15⌉₁₅))`，否則 `F = 30`。
5. 獎勵：到班 `T−F ≤ x < T−15` 或 `T+15 < x ≤ T+F` 得 1 點，每個上班日最多 1 點。

公式說明同時顯示在本頁與「資料品質」頁（同一個 `flexMethodHtml`），依序為：前情提要、資料來源（VD、品質檢查、每分鐘車速、A–F 級、低速分鐘＝E／F 級分鐘、可判讀分鐘）、代號說明（T、t、d、D、r、R、θ、s、h、S、n、n*、W、a、b、C、F、x）、數學符號讀法（Σ、Σ<sub>d</sub>、Σ<sub>t</sub>、max／min、｜S｜、集合寫法、半開區間、∩∪∅、⌈x⌉₁₅），每一步附白話說明，最後以目前選擇的實際數字（含一條道路的低速分鐘與可判讀分鐘加總）示範。方向卡片、長條圖圖例與打卡試算也標上對應代號。θ、R、0.8 近峰係數、0.8 全早壅塞比例、30／120 分鐘都是討論預設值，非官方標準。方向是測點相對公司的位置，不是員工實際路線；晚到側超過 09:30 無多日資料；不估計減少的車流、省時或減塞效果。
