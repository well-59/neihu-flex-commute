# 內科錯峰效益模擬器

平日晨峰，誰移？移多少？省下的時間歸誰？

用臺北市 VD 實測資料校準的內湖晨峰模擬器，作為市府與企業協商分批上班、彈性工時的數據依據。
題目來源：市政 debug 松 issue #4「內湖尖峰車流好比停車場」。

> **目前狀態：** 已套用 2026-10-22 的 VD 實測資料；10-23 的資料收集後補上。

## 真實資料／模擬資料

| 資料 | 來源 | 性質 |
|---|---|---|
| VD 每分鐘流量、速度、佔有率 | 臺北市即時交通資訊 `VDLive.xml` | 真實（兩個平日早上，06:45–10:30） |
| 路段旅行時間 | 臺北市即時交通資訊 `LiveTraffic.xml` | 真實（同上） |
| 路徑旅行時間（各出發時段） | Google Routes API | 預測值 |
| 4 種公司類型的人數、開車比例、上班時間 | 自訂 | **模擬** |
| 背景需求拆分、排隊延滯 | Point queue 模型推算 | 推算 |

本專案不使用任何真實個資，4 種公司類型均為匿名的虛構樣板。

## 結構

```
collector/   每分鐘抓取 VDLive / LiveTraffic（Node，無外部套件）
scripts/     資料處理；make-sample-data.mjs 產生樣本資料
web/         單一頁面儀表板（index.html + data/neihu-data.js）
DESIGN.md    設計稿
```

本機預覽：直接用瀏覽器開啟 `web/index.html`。
可用網址參數預設情境，例如 `?arch=A&pct=30&shift=60&rebound=0&view=after`。

## 模型限制

- 每個通勤口視為獨立的單一瓶頸，不含下游回堵與通勤口之間的互相影響。
- 只有兩天的樣本，不代表長期平均。
- 未建模 capacity drop，可能低估避免排隊的效益。

## 市府 100 天落地

1. 第 1–30 天：交通局開放 VD 歷史序列，建立每 15 分鐘的晨峰基準線。
2. 第 31–60 天：邀 3–5 家內科企業試辦分批上班，以匿名問卷取得通勤方式與路線。
3. 第 61–90 天：試辦期間每天比對基準線，公開儀表板。
4. 第 91–100 天：公布成效，結果納入企業 ESG 揭露與後續獎勵機制。

## 推算方法（假設集中在 `scripts/build-data.mjs` 最上方）

- 延滯：通勤口前方 2 km 的實測車速，與該 VD 早上最快時段的車速相比，算出多花的時間。
- 容量：塞車時段實測流量的平均值。
- 需求：塞車時段 = 容量 + 排隊增加量；順暢時段 = 實測流量。
- 只計汽車（小客車、大客車、聯結車），機車另外記錄。
- 成美橋沒有同名 VD，以新明路端的 VD 代理（待確認）。
