# 內科錯峰效益模擬器

平日晨峰，誰移？移多少？省下的時間歸誰？

用臺北市 VD 實測資料推算內湖晨峰各通勤口的排隊，協助市府與企業討論分批上班、彈性工時。
題目來源：市政 debug 松 issue #4「內湖尖峰車流好比停車場」。

> **目前狀態：** 首頁試算已套用 2026-10-22 的 VD 實測資料，10-23 的資料收集後補上。公司類型仍是虛構樣板。
> 另有 2025 年官方路口調查的實測頁，和 VD 試算分開呈現，沒有把路口通過量直接當作模型需求。

## 真實資料／模擬資料

| 資料 | 來源 | 性質 |
|---|---|---|
| VD 每分鐘流量、速度、佔有率 | 臺北市即時交通資訊 `VDLive.xml` | 真實（2026-10-22，06:45–10:30；10-23 收集中） |
| 路段旅行時間 | 臺北市即時交通資訊 `LiveTraffic.xml` | 真實（同上）；已收集，頁面尚未使用 |
| 六個路口、15 分鐘分車種通過量 | 交工處 2025 年原始 XLSX | 已取得；6/24 與 9/11 兩日樣本，07:00–09:00，09:00–09:30 缺測 |
| 4 種公司類型的人數、開車比例、上班時間 | 自訂 | **模擬** |
| 背景需求拆分、排隊延滯 | Point queue 模型推算 | 推算 |

本專案不使用任何真實個資，4 種公司類型均為匿名的虛構樣板。

## 結構

```
collector/    每分鐘抓取 VDLive / LiveTraffic（Node，無外部套件）
scripts/      build-data.mjs 把收集到的 VD 資料轉成頁面資料；make-sample-data.mjs 產生樣本資料
web/          首頁試算（index.html + data/neihu-data.js）
web/evidence/ 2025 官方路口調查 Dashboard、原始 XLSX、重建程式與既有測試
archive/      本機準備文件、參考版、早期原型與歷史截圖（非現行入口）
DESIGN.md     概念說明
```

本機預覽：直接用瀏覽器開啟 `web/index.html`。
可用網址參數預設情境，例如 `?arch=A&pct=10&shift=60`；另支援 gate、mode、theme。

首頁頁尾「查看 2025 官方路口調查」連到 `web/evidence/index.html`，實測頁可以返回首頁。離線單檔為 `web/evidence/neihu-dashboard-v2.html`。
整合來源、差異與待辦見 [INTEGRATION.md](INTEGRATION.md)。

重建首頁資料：`node scripts/build-data.mjs`（讀取 `data/csv/` 底下的收集結果）。
資料對帳：`python3 web/evidence/data/build.py`。
資料／模型測試：`node --test web/evidence/tests/data-model.test.cjs`。
重新產生實測單檔：`python3 web/evidence/build-standalone.py`。

手動收集：`node collector/collect.mjs --start 06:45 --end 10:30`（主機時區須為 Asia/Taipei，需保持開機與連線）。

## 推算方法（假設集中在 `scripts/build-data.mjs` 最上方）

- 延滯：通勤口前方 2 km 的實測車速，與該 VD 早上最快時段的車速相比，算出多花的時間。
- 容量：塞車時段實測流量的平均值。
- 需求：塞車時段 = 容量 + 排隊增加量；順暢時段 = 實測流量。
- 只計汽車（小客車、大客車、聯結車），機車另外記錄。
- 成美橋沒有同名 VD，以新明路端的 VD 代理（待確認）。

## 模型限制

- 每個通勤口視為獨立的單一瓶頸，不含下游回堵與通勤口之間的互相影響。
- 目前只有一天的 VD 資料；2025 調查也不能代表現今的長期平均。
- 前方 2 km 是假設值，會影響延滯的大小。
- 未建模 capacity drop；偏差方向與幅度尚未驗證。
- 延後的車若超出時間範圍，會被併入最後一格。
- 企業人數轉成車次包含一人一車假設，不能直接當成全體員工的通勤效益。
- 各通勤口的效益只適用獨立模型，未確認路徑重疊前不可加總成全內湖效益。

## 市府 100 天落地（PROPOSED）

1. 第 1–30 天：交通局開放 VD 歷史序列，建立每 15 分鐘的晨峰基準線。
2. 第 31–60 天：邀 3–5 家內科企業試辦分批上班，以匿名問卷取得通勤方式與路線。
3. 第 61–90 天：試辦期間每天比對基準線，公開儀表板。
4. 第 91–100 天：公布成效，結果納入企業 ESG 揭露與後續獎勵機制。
