平日晨峰，誰移？移多少？省下的時間歸誰？

用臺北市 VD 實測資料推算內湖晨峰各通勤口的排隊，協助市府與企業討論分批上班、彈性工時。
題目來源：市政 debug 松 issue #4「內湖尖峰車流好比停車場」。

> **目前狀態：** 首頁試算已套用 2026-10-22 的 VD 實測資料，10-23 的資料收集後補上。公司類型仍是虛構樣板。
> 另有 2025 年官方路口調查的實測頁，和 VD 試算分開呈現，沒有把路口通過量直接當作模型需求。

## 推算方法（假設集中在 `scripts/build-data.mjs` 最上方）

- 延滯：通勤口前方 2 km 的實測車速，與該 VD 早上最快時段的車速相比，算出多花的時間。
- 容量：塞車時段實測流量的平均值。
- 需求：塞車時段 = 容量 + 排隊增加量；順暢時段 = 實測流量。
- 只計汽車（小客車、大客車、聯結車），機車另外記錄。
- 成美橋沒有同名 VD，以新明路端的 VD 代理（待確認）。

## 模型限制

- 每個通勤口視為獨立的單一瓶頸，不含下游回堵與通勤口之間的互相影響。
- 目前只有一天的 VD 資料；2025 調查也不能代表現今的長期平均。
- 前方 2 km 是假設值，會影響延滯的大小。
- 未建模 capacity drop；偏差方向與幅度尚未驗證。
- 延後的車若超出時間範圍，會被併入最後一格。
- 企業人數轉成車次包含一人一車假設，不能直接當成全體員工的通勤效益。
- 各通勤口的效益只適用獨立模型，未確認路徑重疊前不可加總成全內湖效益。

## 2026-10-23：多企業協商第一版（本機）

新入口：[協商實驗室](../../../web/archive/pre-v8/negotiation.html)，原首頁有連結，原單企業試算保留。此版本以單一通勤口「民權大橋東向」和兩家虛構企業驗證操作流程，不代表已執行試辦或已校準交通效果。

- 先核對企業原句、可移動比例與最多延後時間，再人工確認營運與自願參與條件。
- 確定性搜尋比較「較少人調整」「模型等待較少」「最大調整較小」三種偏好；最後一項最小化各企業 `比例 × 延後分鐘` 的最大值，不是實際成本或公平性的驗證。
- 企業退出會恢復原時段車流，重新搜尋其餘企業。沒有達到目標時，不自動套用次佳方案。
- 守恆、非負與完整延後時段由程式檢查。10:30–11:30 的背景可選沿用最後一格需求或補零，11:30 後無新需求是明示假設；持續計算至排隊清空。
- 原始速度色帶與模型排隊分開。容量 ±5% 是固定需求的敏感度，不是信賴區間，也不是全部參數的不確定性。若某容量下基準已無排隊，不計無意義的改善百分比。
- 人數與通過此口的期望車次分開；不宣稱員工個人通勤省時或貨幣收益。

### 啟動與 AI 狀態

直接開 `web/negotiation.html` 可使用離線版。離線版只是嚴格句型解析，接受「甲公司最多10%可晚30分鐘；乙公司最多20%可晚45分鐘」，遇到額外未支援條件會要求補充；不冒充 AI。

實際 AI 模式使用已登入的本機 Claude CLI：

```sh
node scripts/negotiation-server.mjs
```

開啟 `http://127.0.0.1:4173/negotiation.html`。可用 `NEIHU_CLAUDE_BIN` 指定 CLI 路徑、`NEIHU_PORT` 指定埠號。預設尋找 `~/.local/bin/claude`。需要 Node 22+、Claude 登入與網路；CLI 檔案存在只代表已偵測，真正可用以成功解析為準。

橋接僅監聽 loopback，以 `execFile` 和 stdin 執行，不使用 shell 解析輸入；Claude tools 與額外 MCP 關閉，使用 structured output。瀏覽器不取得金鑰；本應用不寫入輸入紀錄。按「整理條件」會將文字送到 Claude，因此示範請維持虛構資料。登入、服務資料政策與用量依使用者既有 Claude 帳號。

語意含糊、缺上限、會議／核心在班／特定群體等目前不能表示的條件，應追問或由人先整理為可移動上限；不自動忽略。原句存在檢查不等於 AI 理解必然正確，人必須核對。網路失敗會明示錯誤；可直接開離線 HTML 使用固定句型。這是本機概念版，不是可公開部署的 AI 後端。

### 第一性原理審查與兩分鐘說法（PROPOSED）

兩位獨立審查者分別檢查交通物理及企業採納邏輯。這是方法借鏡，不代表馬斯克本人意見或偏好。

- 根本需求是讓人可靠到達工作地點。道路短時間服務能力有限；到達量超過服務量就會累積排隊。
- 先確認哪些車次能自願調整、目標時段能否承接，再比較營運與個人作息變動。軟體 request 的延後方式不能直接套在人身上。
- 除了錯峰，減少車次、改變路徑／運具、改善瓶頸服務量也可能解決需求；本版只探索企業彈性時間的可行性。
- 商業價值假說是降低協商與試辦準備成本。誰願付費、企業願意配合多少、員工淨受益多少仍 UNKNOWN。不能把公共交通效益直接當企業收入或 ESG 成效。

可對嚴格決策者這樣說：

> 我們先找出哪些車次真的能移動，再確認目標時段是否容得下。AI 把企業的話轉成可確認限制，程式計算候選安排。這個方案調整較少人，那個方案模型等待較少。現在一家退出，車仍會出現；系統重新安排，或告訴你為什麼未達目標。今天展示的是可追查的情境比較，下一步用自願試辦驗證實際通勤時間、營運影響，以及有沒有把塞車推給另一群人。

4. **試辦討論**：選國際機制、討論營運與自願參與限制、下載本機文字草案。更換入口、條件或機制會清除舊確認。確認僅屬示範紀錄；未送出或保存企業資料。既有 AI 協商原型仍由連結進入，限定 G1 與兩家虛構企業，本頁情境不自動套入。
