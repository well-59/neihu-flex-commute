# 內湖時間島｜未來資源需求

整理日期：2026-10-24。用途：比賽提案與後續協作討論；不加入儀表板的「資料品質」頁。

**狀態：PROPOSED。** 以下為建議協作方式與資源需求，尚未取得局處、企業或經費承諾。金額、試辦名單與時程為 UNKNOWN，須確認範圍後估算。

## 可直接放入提案的摘要

未來需要交通局及交工處協助補齊晨峰逐分鐘車流、車道品質與路段對照；透過產業發展局及園區企業窗口，邀請自願參與者提供彙整的到班時間與通勤路段需求，並請勞動局協助釐清到班安排與勞資溝通事項。經費優先投入資料整理、服務維運、交通專業驗證與小規模試辦。推廣採「路況資訊公開 → 企業自主討論 → 自願試辦 → 成效檢視」逐步進行，不預設企業或員工一定配合，也不把歷史時段差異當成錯峰減塞成效。

## 二、需要補充的資料

| 優先度 | 目前缺口 | 希望取得的資料 | 補齊後可以做什麼 |
|---|---|---|---|
| 優先 | 多日快照只有 07:00–09:30，且缺完整原始分鐘資料 | 相同日期範圍的 07:00–10:30 逐分鐘 VD／路段觀測、缺漏紀錄與來源時間 | 檢查延後到班是否遇到下一波尖峰；更準確判定上班前 15 分鐘的重疊。 |
| 優先 | 即時公開 XML 沒有逐車道診斷旗標；機車完整度未知 | 車道錯誤旗標、設備偵測能力、實際／偵測車道數、分車種分鐘量與可用速度 | 區分零車流與漏測；避免把混合車道速度稱為機車速度。 |
| 優先 | VD、LinkID、SectionID 與線形涵蓋不同，部分走廊使用代理點 | 含有效日期的設備／道路對照、橋梁與匝道測點、線形與通行方向 | 核對公司四方位路段與三條走廊；不以鄰路資料代替。 |
| 優先 | 公司位置與上班時間目前由使用者設定，沒有實際參與資料 | 自願提供的彙整到班時段、可接受彈性範圍、常用路段／交通方式 | 判斷哪些建議值得討論；不蒐集姓名、車牌、住址或個人逐程軌跡作為 MVP 必要條件。 |
| 後續驗證 | 尚無完整路線旅時、排隊長度與合法轉向驗證 | 經授權的路段旅行時間、路口轉向及現地抽樣資料 | 驗證通勤影響；目前不能用測點速度直接估算省時。 |
| 後續驗證 | 低速原因與外在事件尚未整合 | 時間／位置可對照的事故、施工、管制、天氣與特殊活動資料 | 區分常態尖峰與特殊事件，降低試辦前後比較偏差。 |
| 試辦後 | 沒有可歸因的錯峰成效資料 | 試辦前後相同星期／時段觀測、實際採用情形、未參與路段對照及員工彙整回饋 | 檢查是否只是尖峰移轉；不能只用參與前後差值宣稱因果效果。 |

現在實際來源與限制見 [監控盤點](MONITORING-INVENTORY.md)、[TDX API 清單](TDX-API-CATALOG.md)、[已收集歷史資料](../dataset/README.md)。

## 三、經費需求與估算方式

**尚未詢價或核定，不填寫沒有依據的總金額。** 先依「選定路廊、資料天數、試辦期程、使用量及維運責任」確認工作量，再編列下列項目。

| 項目 | 主要用途 | 估算依據／可交付成果 |
|---|---|---|
| 資料工程與前後端人力 | 下載、清洗、版本對照、品質檢核、補齊時段與功能整合 | 各角色投入人月 × 核定單價；交付可重建資料管線與測試紀錄。 |
| 雲端、儲存與維運 | 正式服務主機、歷史檔保存、備份、異常告警、API 使用額度 | 每月用量 × 試辦月數；分列一次性建置與持續維運。TDX 費用依實際方案確認。 |
| 交通專業與現地驗證 | 測點代表性、道路方向、旅時及機車偵測抽樣核對 | 路段數 × 調查時段 × 人力／設備單價；交付校準與限制報告。 |
| 試辦與推廣 | 企業說明、操作教材、匿名彙整問卷、成果回饋 | 場次、參與單位與工時；不以廣告曝光取代實際使用驗證。 |
| 正式上線檢查 | 依承接平台要求進行資安、無障礙與服務交接 | 以具體驗收項目詢價，釐清上線後負責單位。 |

建議先支應「資料可信度＋小規模使用驗證」，確認需求與成效後再評估擴大維運。不把新增 AI 模型、影像辨識或路側設備列為這版 MVP 的必要採購。

## 四、推廣計畫

以下階段為 PROPOSED，不代表已排定時程或已有試辦企業。

| 階段 | 對象與作法 | 要留下的證據／進入下一階段的依據 |
|---|---|---|
| 1. 公開說明與需求確認 | 向園區窗口、企業與駕駛展示熱門路段、資料缺口及公司方位功能；收集使用問題 | 使用者是否理解低速占比、願意查看哪些路段、有哪些到班限制。 |
| 2. 小規模自願使用 | 依資料涵蓋選定路廊，邀請自願企業或員工試用，不指定必須配合的公司 | 實際使用情形、建議相關性、資料完整度與錯誤回報。沒有參與者時，先做觀測服務，不虛構試辦成效。 |
| 3. 自願試辦與追蹤 | 由企業與員工自行討論可行安排；比較試辦前後及未參與路段 | 實際採用情形、是否增加其他時段低速、營運影響與彙整滿意度；同時記錄事故、施工等干擾。 |
| 4. 檢討後擴散 | 公開可重現的方法、成功與無效案例，視結果再洽平台或其他園區 | 以資料可靠、建議可理解、實際需求與可維運性決定是否擴大，不預設減塞百分比。 |

## 對外說明的界線

- 已有道路觀測與公司方位分析，不代表知道員工實際行車路線。
- 「上班前 15 分鐘與低速色格重疊」是討論觸發條件，不是企業必須調整工時的命令。
- 3 公里及低速占比 50% 為目前可調整的示範預設，非官方標準，仍需驗證。
- 未取得合作、資料權限、經費或成效證據前，不寫成已確定資源或承諾。
